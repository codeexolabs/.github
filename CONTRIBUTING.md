# Contributing to CODE:EXO Projects

Thank you for your interest in improving CODE:EXO's code and tooling.
This guide sets expectations for issues, pull requests, and conduct.

## Ground rules

1. **No secrets, ever.** Do not commit API keys, tokens, passwords, or any
   customer data. Push protection is enabled — a failed push means the scanner
   caught something real.
2. **No security vulnerabilities in public issues.** Report privately per our
   [Security Policy](SECURITY.md) — email security@codeexo.com.
3. **Be respectful.** All participants follow our Code of Conduct.

## Getting started

1. Fork the repository (external contributors) or create a feature branch
   (`feat/…`, `fix/…`, `chore/…` prefixes preferred).
2. Make your changes with clear, atomic commits.
3. Ensure tests pass locally before pushing.

## Pull requests

- Keep PRs focused — one logical change per PR.
- Write a clear description: *what* changed, *why*, and *how to test it*.
- Link related issues (`Fixes #123`).
- Passes CI is expected before review; dependencies updated + audited where applicable.

## Issue reports

- Search existing issues first.
- Use a descriptive title and include reproduction steps, environment, and expected vs. actual behavior.

## Licensing

By contributing, you agree your contributions are provided under the
repository's license.

Questions? Open a discussion or reach us at info@codeexo.com.
